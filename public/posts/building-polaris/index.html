Building Polaris: A Wails3 Desktop App

August 1, 2026 — #go, #wails, #desktop — 442 words

My latest project, polaris, is a desktop application built with Wails v3 — a framework that lets you write Go backends with web frontends, compiled into a single binary.

Here’s why I chose it and what the experience has been like.

The Problem

I needed a desktop tool that could:

  • Interact with the local filesystem
  • Run background tasks without blocking the UI
  • Ship as a single binary with no runtime dependencies
  • Look decent without hiring a designer

Electron was the obvious choice, but I didn’t want to ship a Chromium instance with my app. Tauri is interesting but requires Rust, and while I like Rust, I’m faster in Go. Native toolkits (Qt, GTK) felt like overkill for what I was building.

Wails3

Wails v3 is the next major version of the Wails framework. It uses the system’s native webview (WebKit on macOS, WebView2 on Windows, WebKitGTK on Linux) instead of bundling a browser. Your backend is pure Go. Your frontend is whatever you want — vanilla JS, React, Svelte, Vue.

The result is a single binary, typically under 20MB, that starts instantly and uses minimal memory.

Architecture

Polaris has a Go backend handling all the business logic — file I/O, background processing, state management. The frontend is a lightweight web UI that communicates with Go via the Wails runtime bridge.

The frontend calls this like a normal async function, and Wails handles the serialization. It’s surprisingly pleasant.

What’s Working

  • Build speed. wails3 dev starts the app and watches both frontend and backend for changes. Iteration is fast.
  • Binary size. The compiled app is tiny compared to Electron.
  • Native feel. It uses the OS webview, so it feels like a real desktop app, not a website in a box.

What’s Still Rough

Wails v3 is in alpha, and it shows. The documentation is incomplete, some APIs are shifting, and debugging frontend-backend communication can be opaque when things go wrong. But the core is solid, and the community is responsive.

Why This Matters

Desktop apps have been neglected in favor of web and mobile for years. But there’s still a class of tools that need local filesystem access, offline operation, and low latency — and those tools deserve better than Electron’s bloat or native toolkits’ complexity.

Wails3 strikes a balance I’m happy with. Polaris is the first project where I’m using it in earnest, and so far, I’m not looking back.
